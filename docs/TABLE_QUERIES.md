# Table queries

Generated by `npm run tables:status` - do not edit by hand (the mapping is `docs/table-queries.map.json`).
Every direct table query the app sends to Supabase (`sb.from(...)`), and the `/api/v1` endpoint that replaces it.
Each endpoint runs as the signed-in user, so row-level security still applies; a parity test (`tests/parity/tables-*`)
runs the browser's query and the endpoint on the same rows.

The file-storage calls (`sb.storage.from(...)`, rows `storage: <bucket>`) go to `/api/v1/files`: the files stay in Supabase
Storage, and the backend checks the caller against the same rules as the storage policies
(`tests/parity/storage-access.parity.test.ts` compares them for every bucket, caller and kind of path).

The live-update channels (`sb.channel(...)`, rows `live: sb.channel`) go to the WebSocket `/api/v1/live` (protocol: `docs/LIVE.md`).
